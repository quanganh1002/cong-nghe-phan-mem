# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

"Vị Việt" — a multilingual website that narrates traditional Vietnamese dishes and food culture (software engineering course project). It used to be a restaurant ordering app; ordering, cart, login, kitchen pages and the server-side order/menu storage have been removed. All code lives in `project/` (Next.js 16 App Router, React 19, Tailwind v4, shadcn/ui + `@base-ui/react`, TypeScript). UI text and code comments are mostly in Vietnamese. The root `README.md` is empty.

## Commands

Run from `project/` (package manager is pnpm; `package-lock.json` also exists):

```
pnpm install
pnpm dev      # next dev
pnpm build    # next build
pnpm start    # next start
npx tsc --noEmit   # type-check
```

There is no lint script and no test suite. `next.config.mjs` sets `typescript.ignoreBuildErrors: true`, so `pnpm build` does **not** type-check; use `npx tsc --noEmit`. No environment variables are needed for the public site (see Admin below for the optional ones).

After adding or changing English text (UI strings in `lib/i18n.ts` or dish text in `lib/dishes.ts`), refresh the pre-built translations: `node scripts/pretranslate.mjs [lang ...]` (Node 22.6+ and internet; it only translates missing strings, so re-run it if some failed — Google rate-limits, hence its low concurrency).

## Architecture

**Content (`lib/dishes.ts`).** Static list of dishes (`DISHES`). Each has `region` (north/central/south), `category` (main/snack/drink/dessert/festival), optional `image` in `public/foods/` (no image → emoji on a gradient, see `DishVisual`), and Vietnamese + English text with fields `name, summary, origin, culture, ingredients, tip`. To add a dish, add one entry here; every page picks it up. Also add its Google Maps place to `DISH_PLACES` (same file) for the food map; otherwise `/map` falls back to the region's main city.

**i18n.** 10 languages in `lib/languages.ts`. Only Vietnamese and English are hand-written (UI strings in `lib/i18n.ts`, dish text in `lib/dishes.ts`). The other 8 are machine-translated from the English text, keyed by the English string. `lib/translate-client.ts` (`useL10n`) looks up, in order: static tables `public/translations/<lang>.json` (generated by `scripts/pretranslate.mjs`, committed), the localStorage cache (`foodlingo:tr:v1:<lang>`), then falls back to `POST /api/translate` (Google Translate gtx, no key, server memory cache) for whatever is still missing, showing English meanwhile. `useApp()` in `lib/store.tsx` gives `lang`, `setLang`, `dict`; on a first visit it picks the browser language if supported, else `vi`. Dish text goes through `useDishText` in `lib/use-dish-text.ts`. New UI strings must be added to both `vi` and `en` in `lib/i18n.ts`. The dish page shows a machine-translation notice and the original Vietnamese name for non-Vietnamese languages.

**Narration.** `hooks/use-speech.ts` reads text with the browser's speech synthesis (preferring a voice of the exact language); if the device has no voice for that language it falls back to `GET /api/tts` (proxy to Google TTS), and to the default device voice if that fails. Text is split into sentences (`splitText`) and read one sentence at a time, which is what enables the hook's `current` index, `next`/`prev`, `speed` and click-to-seek in the dish page's transcript. Rate changes only apply to a new utterance, so `setSpeed` restarts the current sentence. While reading, the hook holds a Screen Wake Lock (phones stop speech synthesis when the screen sleeps) and registers Media Session handlers (the lock-screen controls only appear in the online-voice `<audio>` mode). The dish page offers a short (name, summary, first sentence of origin and culture) or full narration, remembered in `foodlingo:narration`.

**Glossary & nearby dishes.** `/glossary` lists `GLOSSARY` in `lib/glossary.ts` (Vietnamese + English text, other languages translated like dish text; the term itself is read with the `vi-VN` voice). `/map` has a "dishes near you" card: `PLACE_COORDS` in `lib/dishes.ts` (approximate coordinates, keyed by the `DISH_PLACES` string) + `distanceKm`; add coordinates there whenever a new place is added to `DISH_PLACES`.

**Admin & visitor tracking.** `/admin` (+ `/admin/thong-ke`, `/admin/mon-an`, `/admin/qr`) is guarded by `ADMIN_PIN` (default `1234`, header `x-admin-pin`, checked by `lib/admin-auth.ts`; the PIN lives in sessionStorage via `lib/admin-pin.ts`). `components/presence-beacon.tsx` (mounted in the root layout) sends heartbeats to `POST /api/presence`; the server keeps online devices (`lib/presence-db.ts`, 15s window) and counts visits/dish views (`lib/visits-db.ts`). Storage switches at import time (`lib/supabase.ts`): with `SUPABASE_URL` + `SUPABASE_SECRET_KEY` it uses the tables/RPCs in `supabase/schema.sql` (required on Vercel); otherwise server memory + `data/visits.json`. The admin overview polls `/api/presence` every 2s and diffs the device list (`useLiveEvents`) to show who just joined/left. Heartbeats also carry the visitor's language (`detectLang()` in `lib/store.tsx`, because the beacon's first effect runs before `AppProvider` has read it); dish-page views are counted per language, and a listen (start from idle in the dish page player) is counted via `POST /api/play` (`recordPlay`, per day, dish and language, plus whether it was the short version) and reaching the last sentence by itself counts as a completion (`{done: true}` → `recordComplete`; only when the listen began at sentence 0). `lib/track.ts` holds the client-side senders; `POST /api/feature` counts the secondary features (`near_me`, `near_listen`, `glossary:<id>:term|meaning`, validated against an allowlist). `lib/listening.ts` (`useReportListening`) tells `PresenceBeacon` which dish a visitor is listening to, shown live in the admin overview. Source is `qr` when the URL had `?src=qr` (all generated QR codes add it), otherwise `link`. Admin reads `GET /api/presence` and `GET /api/stats`. When the schema changes, re-run `supabase/schema.sql` in Supabase **before** deploying the code (an unknown `lang` column/RPC argument makes heartbeats fail). QR images: `node scripts/gen-shop-qr.mjs [baseUrl]` writes `qr-codes/`; `/admin/qr` prints them in the browser. Dish content is edited in `lib/dishes.ts`, not through the admin UI.

**Pages.** `/` home, `/dishes` (search + region/category filters, `?region=`, `?cat=`, `?q=`), `/dishes/[id]` (narration player, origin, culture, ingredients, tips), `/map` (food map), `/about`. Language and theme are kept in localStorage under `foodlingo:*` keys.
